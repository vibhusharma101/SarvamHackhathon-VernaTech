# Security audit: initial scaffold (pre-first-commit)

_Generated by /vii-cso. No base branch/SHA yet — full working tree reviewed as the diff._

## Surface
- New endpoints: `POST /sessions`, `GET /sessions`, `GET /sessions/{id}/scorecard`, `GET /sessions/{id}/latency`,
  `POST /sessions/{id}/upload`, `POST /sessions/{id}/score`, `POST /sessions/{id}/rescore`,
  `POST /sessions/{id}/writeback`, `POST /harness/run`, `GET /harness/results`, `POST /admin/reset`,
  `WS /sessions/{id}/stream`.
- New external calls: Sarvam REST (`api.sarvam.ai` — STT batch/translate, chat completions, TTS), Beeceptor
  (mocked ATS writeback), Slack incoming webhook. All target URLs come from server-side env vars, not user
  input — no SSRF surface.
- New env vars: `SARVAM_API_KEY`, `SARVAM_API_KEY_BACKUP`, `SUPABASE_URL`, `SUPABASE_SERVICE_KEY`,
  `SUPABASE_BUCKET`, `BEECEPTOR_URL`, `SLACK_WEBHOOK_URL`, `CORS_ORIGIN` (api); `NEXT_PUBLIC_API_BASE`,
  `NEXT_PUBLIC_WS_BASE` (web — client-visible by design, `NEXT_PUBLIC_` prefix).
- New deps: fastapi, python-multipart, uvicorn, pipecat-ai[sarvam], python-dotenv, supabase, websockets,
  numpy, pydantic, httpx (api, unpinned); next 16.2.12, react 19.2.4 (web, pinned via package-lock.json).

## Findings

### HIGH
- `api/app/routers/admin.py:16-24` — `POST /admin/reset` has no authentication, authorization, or rate
  limiting, and it truncates every session, turn, score, and harness row. `NEXT_PUBLIC_API_BASE` is baked
  into the client JS bundle by design (Next.js public env var), so the API's base URL is trivially visible to
  anyone who opens dev tools on the deployed site. **Attack:** `curl -X POST <public-api-url>/admin/reset` from
  anywhere, anytime — including seconds before the team's demo. **Fix:** require a shared-secret header
  (`X-Admin-Token`, compared against an env var) on this one route at minimum; full auth is out of scope per
  PRD, but a destructive endpoint needs more than "nobody will guess the URL."

### MEDIUM
- `api/app/routers/sessions.py` (all routes) + `scoring.py`, `writeback.py`, `harness.py` — no
  authentication/authorization anywhere in the API. `GET /sessions` enumerates every candidate's name, role,
  language, and scores with no auth; `GET /sessions/{id}/scorecard` returns original-language evidence quotes
  (potentially identifying interview content) to anyone who has or guesses a session UUID; `POST
  .../writeback` lets anyone re-trigger a POST to the team's Slack channel for any session. This is a
  **known, documented scope exclusion** — PRD §3 explicitly lists "Real auth" as out of scope for the 6-hour
  build — so this isn't a regression the diff introduces by accident, it's a decision already made. Flagging
  it anyway because the PRD's own build plan calls for a **public** Vercel + Railway URL, and Hour 6's
  checklist tests it "from another device" — meaning this data really will be reachable by anyone with the
  link once deployed, not just the team. Acceptable for a hackathon demo using team-recorded/consented paired
  profiles; would need real auth before this touched any candidate who didn't explicitly consent to public
  exposure of their transcript.
- `api/requirements.txt` — no version pins on any dependency. A `pip install -r requirements.txt` run next
  week could silently pull a different (potentially vulnerable or breaking) release than what was tested
  today. No lockfile exists for `/api` (unlike `/web`, which has `package-lock.json`). Recommend pinning after
  the first successful install (`pip freeze > requirements.txt` or add `==` version specifiers) once the
  pipeline dev has a working environment.

### LOW
- None beyond what's already covered above — CORS is configured with a single explicit origin from env (not
  a wildcard), `allow_credentials=True` is paired with that single origin correctly, and no secrets are
  committed anywhere (`.env.example` files contain only empty placeholders; `.gitignore` excludes real `.env`
  files in both `/api` and `/web`).

## Post-audit fix
`api/app/routers/admin.py` now requires an `X-Admin-Token` header matching a new `ADMIN_TOKEN` env var (added
to `.env.example`, empty by default). The check fails closed — if `ADMIN_TOKEN` isn't set, every request to
`/admin/reset` gets a 403, not an open door. Re-verified the app still imports and boots cleanly after the
change. MEDIUM findings are unchanged (documented scope decisions, not regressions — see above) and are not
ship-blocking.

## Verdict
**CLEAR.** The one HIGH finding is fixed and re-verified. Two MEDIUM findings remain as informational —
the no-auth-on-read-endpoints decision is already documented in the PRD as an accepted hackathon-scope
tradeoff, and the unpinned `requirements.txt` is a hygiene item for whoever installs the pipeline deps next,
not an exploitable regression today.
